# Design

## Context

The Cypress infrastructure from the archived `setup-cypress-desktop` change is in place: `cypress.config.ts` (baseUrl `http://localhost:5276`, 1600x900 viewport), `cypress/support/tauri-mock.ts` (pre-load bridge mock with per-command canned responses), `cypress/support/e2e.ts`, and one smoke spec. The app is a React 19 + Vite SPA whose native access funnels through `window.__TAURI_INTERNALS__.invoke`, plain `fetch` for geocoding, and the browser File System Access API (`showSaveFilePicker`) for saves in a browser environment.

Key seams discovered from source reading:

- **EXIF parsing is real and worker-based** (`src/hooks/useExifData.ts` → `exifWorker` + exifreader). It needs genuinely EXIF-bearing image files; stubbing the worker would bypass the app's real data contract.
- **Save/export** goes through `window.showSaveFilePicker` when present (browser mode), falling back to an anchor download — a single stub point.
- **Geocoding** is plain `fetch` to an external API — interceptable with `cy.intercept`.
- **Updater** resolves through `@tauri-apps/plugin-updater` `check()` → invoke commands — registerable in the existing tauri-mock.
- **Theme** is `data-theme` on `<html>` (per DESIGN.md) — directly assertable.

## Goals / Non-Goals

**Goals**
- Comprehensive, fast, deterministic coverage of user-visible flows in a real browser.
- Control EXIF data end-to-end via real fixture files so parsing → state → UI is exercised honestly.
- Keep every spec network-isolated and self-booting.

**Non-Goals**
- Real Tauri IPC or compiled-binary testing.
- Replacing Jest unit tests; plugging a11y-linter tooling (axe etc.) into Cypress.
- Pixel-perfect visual regression testing.

## Decisions

1. **Real binary EXIF fixtures generated by ImageMagick, committed to the repo.** A `scripts/generate-e2e-fixtures.sh` (documented in the fixture README) creates `cypress/fixtures/images/`: `full-exif.jpg` (GPS coords, camera make/model, DateTimeOriginal, exposure, ISO, focal length), `no-gps.jpg` (camera metadata, no GPS), `corrupt.jpg` (truncated/garbage bytes with `.jpg` name), plus a KML fixture for import. Fixtures are verified at generation time with exifreader (available in the workspace) so their embedded values are known constants the specs assert against. Alternative considered: stubbing the exif worker via `cy.intercept` of the worker script — rejected as fragile and it would stop testing the real parsing path.

2. **Shared boot helper with a standard environment.** `cypress/support/app.ts` exports `bootApp(options)` wrapping `cy.visit('/', { onBeforeLoad })` with: tauri-mock installed, standard command registrations (`plugin:app|version`, updater check), a stubbed `window.showSaveFilePicker` recording calls into the window for assertions, and default `cy.intercept` for geocoding. Specs opt into overrides (e.g. updater returning an update). This prevents per-spec environment drift.

3. **Network isolation via `cy.intercept` with `forceNetworkError`-style defaults.** Geocoding intercepts return canned reverse-geocode JSON per test needs; a catch-all intercept asserts nothing unexpected escapes (fail loudly on unmocked external hosts).

4. **One spec file per feature area** (upload, exif-display, views, map, investigation, export-import, settings, theme, comparison, updater, a11y) rather than one mega-spec — keeps run reports diagnosable and allows `--spec` filtering.

5. **Lazy-loaded views get grace.** Map/Investigation are `React.lazy`; specs assert against `data-testid` hooks that already exist (`map-container`, `lazy-investigation`, etc.) and use Cypress retry semantics instead of sleeps.

6. **Bugs found are not absorbed by tests.** If a spec exposes a real app bug, it is reported to the user and the spec asserts current behavior only when the failure is a test artifact, never silently adjusted.

## Risks / Trade-offs

- ImageMagick's EXIF writer covers common tags; if a needed tag can't be written, the fixture script falls back to a hand-built minimal EXIF APP1 segment (documented in the script).
- Clipboard assertions depend on browser clipboard permissions — the helper grants them in `onBeforeLoad` via `navigator.clipboard` stub where the permission API is unavailable in the runner.
- `cy.intercept` catch-alls on external hosts must whitelist `localhost:5276` traffic (Vite HMR/websocket is not HTTP-intercepted but kept in mind).

## Migration Plan

Additive only: new support files, fixtures, specs, and one script. Existing smoke spec stays. No app source changes expected.
